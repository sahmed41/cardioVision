# CardioVision

## CardioVision: AI-Powered ECG Analysis Progressive Web Application
CardioVision is a Progressive Web Application (PWA) designed to aid in the fast and accurate preliminary classification of Electrocardiogram (ECG) images to assist in cardiovascular disease (CVD) management. The application uses a hybrid architecture combining web technologies for the frontend/backend and a deep learning computer vision model for ECG analysis. It is designed to act as an auxiliary digital assistant for general practitioners—augmenting their workflow rather than replacing human medical expertise.

## 🚀 Key Features
### For Patients
- Secure Access: Patients log in securely using their National Identity Card (NIC) number.
- ECG Digital Upload: Upload an ECG report via a digital image file or capture it directly using a mobile camera.
- DocCode Security Mechanism: To prevent risky self-diagnosis and avoid physician inbox spam, patients can only upload and interpret an ECG if they provide a unique, single-use DocCode generated by their doctor during their consultation.
- Mild Messaging: Automated preliminary results are displayed in a mild, reassuring manner (e.g., instructing the patient to contact their doctor without inducing panic).

### For Physicians
- Consultation & Code Generation: Primary physicians record patient details (medical history, family history, symptoms, allergies) and generate a unique DocCode for the patient.
- Pending Diagnose Queue: Accesses a dedicated list of uploaded ECGs awaiting physician verification.
- ECG Verification & AI Evaluation: View the uploaded ECG, evaluate and confirm/deny the automated AI classification, and write final clinical interpretations.
- Patient History Profile: Retrieve and review comprehensive historical patient data, including previous ECGs, to monitor progressive cardiac changes over time.
- Collaborative Second Opinions: Search for and securely share patient ECGs with third-party physicians to collaborate and gather second opinions within the system.

## 🛠️ System Architecture

The CardioVision system uses a decoupled architecture where the frontend application communicates with the backend and integrates with the deep learning model through an API.

1. First (primary/prescribing) physicians talk to patients during the consultation and ask
them questions and record their answers in the CardioVison application.
2. The physician generate a code called the DocCode.
3. The doctor give the code to the patient.
4. That patient will go and get an ECG test, log in to the CardioVision app and will upload
a picture, scanned copy or digital version of the ECG using the CardioVision application
by providing the DocCode. The DocCode is unique to each patient on each visit. It can
only be used once.
5. The CardioVision AI will then interprets the uploaded ECG result and show it to the
patient. If there is an abnormally, the application would instruct the patient to contact
the physician as soon as possible without panicking the patient by telling something is
wrong with them but if the readings are normal, the application would inform the patient
to wait for physician interpretation before making any decisions.
6. Afterwards, the report is sent to the physician who prescribed the test. Physicians will
receive a notification as soon as the result is sent them. Further, all the reports they
have to interpret will be show to them in a list and; the results that are abnormal will
be coded in orange colour and normal will be coded in green colour. So, physicians can
prioritise and manage.
7. If the physician who prescribed the test wishes, the physician can share it with other
doctors (second physicians) to get their opinion.
8. Second physicians can view the colour coded list similar to presicribing physicians.
9. Second physicians can share their opinion on the ECG reports shared with them.
10. Primary physicians can view the opinion of the second physicians.



## 🛠️ Tech Stack
- Frontend: HTML5, CSS3 (custom styles for responsive, mobile-first layouts), JavaScript (ES6+), and jQuery (for simplified DOM manipulation and seamless AJAX interactions).
- Backend: PHP (server-side logic governing session authentication, profile routing, consultation creation, and database bridge).
- Database: MySQL relational database consisting of four core tables:
  - User: Stores credential data, credentials, identities, and authorization roles (patient vs. physician).
  - Consultation: Stores general clinical consultation entries (symptoms, allergies, medical history, associated DocCode).
  - Diagnosis: Contains raw uploaded ECG image file locations, AI classifications, physician's validation status, and final clinical text interpretations.
  - Second Opinion: Houses third-party physician references, comments, and collaborative medical opinions.  
- AI Model - Binary classification VGG-16 deep learning model.
- API: FastAPI web framework running in Python, hosting the binary classification model.

## 🧠 Deep Learning Model Details
The core AI engine is a VGG-16 pre-trained Convolutional Neural Network (CNN), fine-tuned using TensorFlow and Keras to classify digital 12-lead ECG report images into Normal or Abnormal classes.

## 🧪 Testing and Security

CardioVision was subjected to three distinct phases of validation to ensure safety, performance, and legal compliance in medical contexts:

- Functionality Testing: Full test suites mapped to both Patient and Physician functional requirements (e.g., verification of DocCode generation, ECG image capture/upload, and second opinion sharing) achieving 100% success.
- User Acceptance Testing (UAT): Underwent alpha UAT with real physicians (evaluating its clinical feasibility and diagnostic utility) and patients (assessing readability and usability).
- Security Testing: Audited to guarantee five core security objectives:
- Confidentiality: Protected medical data storage ensuring unauthorized entities cannot access patient profiles.
- Integrity: Verified data is safely stored and remains unchanged from its uploaded state.
- Availability: Maintained high uptime for clinicians on the move.
- Authorization: Role-based access controls dividing clinical operations from patient tools.
- Non-repudiation: Complete, immutable database records logging every system transaction (e.g., exact times patients uploaded reports, and exact times physicians validated interpretations).
